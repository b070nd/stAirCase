# v1.0.0 readiness

What stands between today's master and a v1.0.0 candidate, requirement by requirement. It is a gate record, not a
release: it creates no tag, no release and no Marketplace listing, and it says **not ready** until every row is *met* or
carries an accepted disposition. The statements in [the draft notes](v1.0.0-notes-draft.md) may only use what is *met* here.

**As of** master `9f061dd` (2026-10-07). Update the SHA when you update a row.

Words: **met** (built, tested, evidence named), **accepted** (the owner accepted a stated limit; quoted in the notes),
**pending** (not met, and the owner has not accepted leaving it), **owner** (only the owner can do the step).

## What a v1.0.0 candidate still needs

1. **OpenCode**: decide whether it is inside the 1.0 promise (needs more real runs: other tools, the ungated-change
   control) or listed as experimental outside it, as the draft notes now do.
2. **The ruleset run (US-012)** in the owner's test repository, and its evidence kept.
3. **A candidate commit**: a `chore: prepare v1.0.0` change folding the CHANGELOG's Unreleased section, naming the supported
   host versions, and turning [compatibility](../compatibility.md)'s "before 1.0" into the 1.0 promise for the six contracts;
   then `make evidence` on that exact commit, and CI, CodeQL, Scorecard green on it.
4. **Ordering against the Bash line**: the CHANGELOG still carries the earlier Bash releases 1.0.0 to 1.2.0. A Go v1.0.0
   orders after them for people on that line only through the Homebrew formula's `version_scheme 1`; say it in the upgrade
   notes, or choose another number (owner).
5. **Owner steps**: tag, push, the tap, and the GitHub release draft.

Not part of this gate: the hosted website (a separate beta) and the Marketplace listing (US-014, after 1.0).
